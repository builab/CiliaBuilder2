General: File Types

CiliaBuilder2 works with two kinds of files: repeating units (maps, atomic models and 3D objects) that are attached to particles, and particle lists and sessions (STAR and JSON) that describe the model. Repeating units are opened with the standard ChimeraX open command and then chosen on the Attachment page. STAR and JSON files are loaded and saved from the Save/Load page.

Preparing a repeating unit

Every map, atomic model or GLB should be oriented with the long axis of the filament parallel to the Z axis before it is attached. The z_align_*.cxc scripts in the example folder show how to do this for an EMDB map: copy the map, rotate the copy with roll, resample it onto the original grid with volume resample, and save the result as a new .mrc file. Any remaining rotation about Z can be set with Attachment Z rotation on the Attachment page.

Map (.mrc, .map, .ccp4, EMDB)

A density map of one repeating unit. Open a local file or fetch directly from the EMDB:

    open emd_2132_zaligned.mrc
    open emdb:2132

  • Each copy is placed by the centre of the map box, so the repeating unit should sit at the centre of its box.
  • The map's origin is ignored when attaching; only the grid size and voxel size matter.
  • Maps fetched from EMDB are stored in the session JSON by their EMDB ID and are fetched again when the session is loaded.
  • Maps are the most faithful but heaviest option. For a full-length cilium with hundreds of copies, consider a GLB surface instead.

Atomic model (.pdb, .cif, .mmcif)

An atomic model of one repeating unit, opened from a file or fetched from the PDB:

    open mymodel.cif
    open pdb:9fqr

  • By default each copy is placed by the centre of the model's bounding box.
  • If the model was fitted into a map and should be placed exactly where that map would be, open the map as well, enable Use fixed center for GLB & PDB and press Read center coordinate from map.
  • Models fetched from the PDB are stored in the session JSON by their PDB ID.

GLB (.glb, .glb.gz)

A GLB file (binary glTF) holds a coloured triangle surface. It is much lighter than a map or atomic model and is the recommended format for large models. A GLB is usually made in ChimeraX from a map: display the map surface at the desired threshold and colouring, then save it with save. A .glb.gz file is simply a gzip-compressed GLB (gzip mymap.glb); it is much smaller and opens like a normal GLB.

Guideline: always save map GLB files with center false

    save mymap.glb models #1 center false

By default ChimeraX moves the scene to the origin when it writes a GLB file, so the surface no longer has the same coordinates as the map it came from. With center false the GLB keeps the map's coordinates. You can then enable Use fixed center for GLB & PDB, press Read center coordinate from map with the source map selected, and the GLB is placed exactly where the map would be. Several GLB files made from the same map (for example, one per protein colour) then also stay aligned with each other.

  • Without a fixed centre, each copy is placed by the centre of the GLB's bounding box.
  • When a session is saved, GLB files are exported next to the JSON file with their current colouring, so the session folder can be moved to another computer.
  • Drawings made on the Geometric drawing page are saved in the same way (Save drawing as GLB).
  • STL surfaces (.stl) can be attached in the same way.

STAR (.star)

A RELION-style particle list. CiliaBuilder2 writes one STAR model per build (microtubules, central pair, IFT train) and can import STAR files made by other programs with Load STAR file, to build custom geometries such as curved cilia or transition zones.

column required on import description
rlnCoordinateX / Y / ZyesParticle position, in pixels.
rlnAngleRot / Tilt / Psino (default 0)RELION Euler angles giving the particle orientation, in degrees.
rlnImagePixelSizeno (default 1)Pixel size in Å. Coordinates are multiplied by it on import.
rlnHelicalTubeIDno (default 1)Filament number. Each microtubule has its own ID (1–9 for the outer ring).
rlnTomoNameno (default TS_001)Tomogram name; carried through but not used for placement.
rlnClassNumberno (default 1)Build number; each new STAR model gets its own class number.

Files written by CiliaBuilder2 use a pixel size of 1 Å, so their coordinates are directly in Ångström. For STAR files with several data blocks, the first loop that contains the coordinate columns is read. Session JSON (.json)

Save session JSON writes the whole CiliaBuilder2 model to a single JSON file, and Load session JSON rebuilds it. A session file stores:

  • the tool settings shown in the CiliaBuilder2 window;
  • every generated STAR model, including its particle rows;
  • generated membranes and geometric drawings;
  • the attachment sources (maps, atomic models, GLB files), recorded by EMDB/PDB ID when fetched, or by file path otherwise;
  • each attachment, with its rotation and fixed-centre settings, display state and colours;
  • the arrangement of the models in the ChimeraX model panel.

Keep local maps and atomic models at the same path when moving a session. If a file cannot be found when loading, CiliaBuilder2 asks you to locate it. A CiliaBuilder2 session JSON is separate from a ChimeraX session (.cxs).

Example sessions are in the example folder; see Tutorials.
